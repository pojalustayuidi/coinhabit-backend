# Проверки backend

Workflow `.github/workflows/backend.yml` запускается для pull request и при изменении main.
В нём два задания:

- `tests`: сборка и тесты трёх сервисов с PostgreSQL и RabbitMQ;
- `smoke`: запуск полного Compose и HTTP-проверки авторизации и владения данными.

## Локальный запуск

Подготовка окружения описана в [инструкции запуска](WINDOWS_SETUP.md).
Для Gradle на Windows нужен JDK 25 и переменные окружения из `.env`.

```powershell
auth-service\gradlew.bat -p auth-service build
habit-service\gradlew.bat -p habit-service build
savings-service\gradlew.bat -p savings-service build
```

Отчёты: `<service>/build/reports/tests/test/index.html`.

В тестах авторизации проверяются регистрация без подтверждения, добровольное подтверждение,
ошибка SMTP, независимость гостей, сохранение UUID при регистрации гостя и ошибки доступа.
Отдельные тесты проверяют миграцию существующих аккаунтов, JWT и лимиты создания гостей.

## Проверка полного стека

Только для одноразового тестового окружения: скрипт создаёт аккаунты, привычку, цель и
подтверждённую транзакцию в БД. Для проверки сбоя SMTP установить SMTP_HOST=127.0.0.1,
SMTP_PORT=1 и запустить Compose без mail-профиля.

```powershell
docker compose up -d --build
python scripts/smoke_auth.py
```

Скрипт проверяет запрет доступа к чужим данным и сохранение привычки, цели и накоплений
после преобразования гостя. Также проверяет недействительные JWT во всех сервисах.

Результаты CI находятся в разделе Actions репозитория. Успешный запуск проверяет конкретный
коммит и не заменяет проверку запуска на компьютере разработчика.
